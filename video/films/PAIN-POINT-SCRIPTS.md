# The pain-point films: scripts

Two films, one person each, each built on a pain the other tools leave alone. Both are silent and carry their
words on cards; both start from an empty account and open on the finished result.

How the two writing modes were used. The **tension cards** (the opening and the close) are written in the Bob
Speak mode: name the comfortable assumption, then say what happens in practice, in short landing lines. The
**step cards** are written in the Ina Koleva mode: say what we do next, in order, make the problem visible with
one small example, and show the same test before and after. Neither film claims to be written or approved by
either person; the modes are ways of writing.

Truth notes for both: every screen is the real app, captured from the current build with made-up data. Nothing
here is released yet, and the end card says so. No figures for time saved or adoption appear, because none have
been measured.

## Film 1: Dana, agency reporting lead (98 s)

**The pain.** One report for every client usually means one copy per client, and copies drift.
**What only GridZero does here.** One report; each viewer is held to their own rows, and the server never sends
them anyone else's figures.

| Beat | Words on screen | Real screen |
|---|---|---|
| Open | (none) | The client's view: "You see this report for client: Birchwood Coffee", total 32,550 |
| Tension | A report for every client / usually means a copy for every client. | card |
| Tension | Copies drift. / One of them is always wrong. | card |
| Promise | Build it once. / Here is how, from an empty account. | card |
| Step 1 | Add the orders / one file, every client in it | Home, Upload a file; the import preview; the table |
| Step 2 | Build the report yourself / no analyst, no waiting | "Add a card from a table": total, then total by client; the report |
| Step 3 | Know what you are looking at / a filter says whether it reached the card | Last 30 days with compare: 12,229, down 281, "Filtered" on each card |
| Step 4 | Share it once / and hold each person to their rows | Share: invite, "Limit what they see", client is Birchwood Coffee |
| Step 5 | What the client gets / their rows, their totals | The client's report: the banner, 32,550, one bar |
| Close | You see 112,050. They see 32,550. / Nobody else's numbers leave the server. | card |
| End | GridZero / In review. Not yet released. | end card |

The before and after is the same report seen by two people: 112,050 for Dana, 32,550 for the client.

## Film 2: Priya, data lead (88 s)

**The pain.** Every BI tool has an assistant now, and none can show that an answer it gave is still right.
**What only GridZero does here.** The data is modelled without an analyst, a person is asked only what the data
cannot settle, and an answer marked correct becomes a test the agent is put through again.

| Beat | Words on screen | Real screen |
|---|---|---|
| Open | (none) | Checked answers: "Agent gets it right" |
| Tension | Every BI tool has an assistant now. / Which of its answers were right last week? | card |
| Tension | A badge is not a test. / So we made the answer one. | card |
| Step 1 | Add your data / an orders export, nothing set up | Home, Upload a file; the table |
| Step 2 | Ask in plain words | The Ask bar: "What was revenue?"; the reply, 179,400, and "one thing decides this number" |
| Step 3 | It models the data itself / and asks the one thing it cannot know | Needs you: "Settled without asking", then the question with 161,160 against 179,400; Confirm |
| Step 4 | Ask again / then say it is right | The reply, 161,160; "Mark as correct" |
| Step 5 | Now it is a test / the agent is asked again and graded | Checked answers: "Test the agent again", then "Agent gets it right" |
| Close | Confirmed once. / Checked every time the agent changes. | card |
| End | GridZero / In review. Not yet released. | end card |

The before and after is the same question asked twice: 179,400 before anyone decided what counts, 161,160 after.

**Staged in film 2.** The agent's sentences come from a scripted stand-in model. The numbers in them are the real
totals of the made-up table, the queries really ran, and the grading ("Agent gets it right") is the app's own.
A real model has not been filmed.
